# Telegram bot behaviour

Library: `tgbotapi` (inmo). Webhook only in production (`TelegramWebhook.kt`). Header `X-Telegram-Bot-Api-Secret-Token` must equal `TELEGRAM_WEBHOOK_SECRET`. Valid update → **200** immediately; work on webhook scope. Bad secret → **403**.

Logs: `RedactingKSLog` strips bot token and `/bot<token>` URL fragments.

## Commands and messages (`TelegramHandlers.kt`)

- `/start`: local text from `startTextMessage(firstName)`. Greeting voice is `TODO("Greeting voice is not implemented on the walkie-talkie ai-service")` and that string is replied in the chat. `NotImplementedError` is not rewritten to `ERROR_TEXT`.
- **Voice**: `ensureSession` is a no-op (history starts on `session_id`). Queue then `POST {AI_SERVICE_BASE_URL}/api/v1/walkie-talkie` with form `session_id` + file `audio`. Response JSON: `transcript`, `response_text`, `audio_base64` WAV. Notes stay empty — `TODO("Grammar notes (wrong|||better) are not implemented on the walkie-talkie ai-service")` in `HttpClipClient`, the quote is the transcript only. WAV is transcoded with `ffmpeg` to OGG/Opus before `sendVoice`. Other failures → `ERROR_TEXT`.
- Non-command **text** → `Please send a voice message.`
- Other content: ignore.

Queue copy:

- Behind others: `Got it — I'll answer in order.`
- Full: `Too many voice messages at once. Wait for my reply, then send again.`

Voice download is OGG (`voice.ogg`, `audio/ogg`). The Ktor image installs `ffmpeg` so a WAV reply can be sent as a Telegram voice note. Host for this client is `AI_SERVICE_BASE_URL`; the same variable is still what CMP realtime/review calls.

## Coaching quote (`CoachingFeedback.kt`)

Separator `|||`. `parseCorrections` keeps only two non-empty sides. At most **3** notes used.

Telegram entities: line `🗣️ You said:` then a **blockquote**. Each matched `wrong` in the transcript is **strikethrough** on its own line, then **bold** `better` on the next line. Unmatched `wrong` is skipped. A match counts only as a whole word or phrase (letters/`'` on either side block it), so `me` does not cut `remember`. Overlapping spans: first non-overlapping after sort by start, longer wins on same start. Trailing `. ! ? , ;` after a span is kept with the span so it does not orphan on the next line.

If transcript is blank, **no** text quote is sent (voice still sent).

## LLM (`ai-service/app/llm.py`)

Two completions in `ClipPipeline` (`asyncio.gather`):

- **Reply** (`REPLY_SYSTEM`): JSON `{"reply"}` only. Conversation partner; history included; `temperature` 0.7. No corrections in reply.
- **Notes** (`NOTES_SYSTEM`): JSON `{"notes":[{"wrong","better"}]}` or `[]`. Transcript only; `temperature` 0. Empty list only if already grammatical. Six few-shots teach span width (whole grammatical utterance; one word; short phrase; expand for a missing word; expand for an extra word; two holes). Not a grammar taxonomy.

`wrong` must be an exact contiguous whole-word substring of the transcript (Kotlin skips unmatched and in-word hits). Parser maps objects (or pre-joined strings) to `wrong|||better`. Max 3 notes. `max_completion_tokens` 500, `response_format=json_object`. Default model env `LLM_MODEL` = `openai/gpt-4o-mini` via OpenRouter (`OPENAI_BASE_URL` default `https://openrouter.ai/api/v1`). Key env name is still `OPENAI_API_KEY`.
