# Telegram bot behaviour

Library: `tgbotapi` (inmo). Webhook only in production (`TelegramWebhook.kt`). Header `X-Telegram-Bot-Api-Secret-Token` must equal `TELEGRAM_WEBHOOK_SECRET`. Valid update is queued, then **200**. Bad secret → **403**. A handler that drops the update after 200 is a permanent loss: Telegram will not retry.

Logs: `RedactingKSLog` strips bot token and `/bot<token>` URL fragments.

## Commands and messages (`TelegramHandlers.kt`)

- `/start`: any message whose first token is `/start`, including `/start@bot` and `/start payload`. `onCommand` alone drops a command that is not a single bot-command entity, and the text handler used to ignore every line starting with `/`, so that update got 200 and no reply. Greeting is sent with `allowSendingWithoutReply`. Log the Telegram message ids of the text and the voice. Then `ai.startSession(sessionId)` (POST session + greeting audio), text from `startTextMessage(firstName)`, then `sendVoice` greeting. Uses private-chat first name when present.
- `/streak`: same first-token rule, including `/streak@bot`. `setMyCommands` registers `start`, `profile`, `streak`, and `onboarding` after the webhook is set. The reply is one photo of the rolling Moscow week (six days back through today, rightmost is today), with the current streak and a random short cheer as the caption. The card is a white rounded panel on cream `#FBFAF6`, in Inter. A practiced day is blue `#1874FC` with a white check and a glow, a missed day is a light circle with a gray cross, and today with no voice is an empty outline. The date range is that window, not a fixed string. A failure to load the profile replies with `ERROR_TEXT`. If the photo cannot be sent, only the caption goes out. Duplicate delivery from `onCommand` and the text handler is deduped by chat id and message id.
- **Voice**: `ensureSession` then queue. On complete, if the transcript is non-blank, `coachingEntities(transcript, corrections)`, then `sendVoice` reply OGG. The streak photo is not sent here; it is only the `/streak` command. Failures of the clip itself → `ERROR_TEXT`.
- Non-command **text** → `Please send a voice message.`
- Other content: ignore.

Queue copy:

- Behind others: `Got it — I'll answer in order.`
- Full: `Too many voice messages at once. Wait for my reply, then send again.`

Voice download is OGG (`voice.ogg`, `audio/ogg`).

## Coaching quote (`CoachingFeedback.kt`)

Input is `List<Correction>` (`speaking/ClipProcessor.kt`): `wrong`, `better`, `kind` (`GRAMMAR` / `WORD` / `NATURAL`, or `null`). `HttpClipClient` builds it from `result.corrections`; if that is empty it falls back to legacy `result.notes` (`wrong|||better`, `parseCorrections`) with `kind = null`.

Priority `grammar` > `word` > `natural` > no kind. At most **3** corrections: sorted by priority, then `take(3)`, so natural never pushes out grammar.

Telegram entities: line `🗣️ You said:` then a **blockquote**. Each matched `wrong` in the transcript gets, when `kind` is set, an *italic* Russian label on its own line above it (`StartMessage.kt`): `Грамматически верно:`, `Лучше подойдёт слово:`, `Нейтив сказал бы так:`. Then `wrong` in **strikethrough** on the next line, then **bold** `better` on the line after. Unmatched `wrong` is skipped. A match counts only as a whole word or phrase (letters/`'` on either side block it), so `me` does not cut `remember`. Overlapping spans: higher-priority kind wins; same kind → earlier start, then longer. Chosen spans are rendered in transcript order. Trailing `. ! ? , ;` after a span is kept with the span so it does not orphan on the next line.

If transcript is blank, **no** text quote is sent (voice still sent).

## LLM (`ai-service/app/llm.py`)

Two completions in `ClipPipeline` (`asyncio.gather`):

- **Reply** (`REPLY_SYSTEM`): JSON `{"reply"}` only. History included; `temperature` 0.7. Spoken turn is about three to six sentences: a specific reaction to what they just said, then one question that continues it. Same manner in onboarding and realtime (`app/voice.py`). No corrections in the reply.
- **Notes** (`NOTES_SYSTEM`): transcript only, `temperature` 0, 1200 output tokens. The model selects useful, reliable errors in spontaneous speech and returns display pairs plus internal confidence, reason, ASR/artifact and usefulness decisions. The code requires all checks to pass, validates exact whole-word context, removes duplicates/overlaps and returns at most three public `Correction(wrong, better, kind)` values. Empty output is valid for uncertainty, normal spoken language or lack of a useful self-contained pair. Legacy bare model strings and missing/unknown categories are rejected; the outgoing legacy `wrong|||better` format remains supported for clients.

Grammar is a genuine grammatical error; word is an incorrect word/collocation for the intended meaning; natural is clearly unidiomatic phrasing, never a merely fancier alternative. Spoken fillers, self-repair, ASR punctuation and regional variants must not trigger corrections. The fragment should be minimally sufficient to understand the error, not minimally short. See [shared spoken-correction policy and evaluation](2026-09-30-spoken-corrections.md).

The spoken reply retains its existing token budget. Both calls use `response_format=json_object`. Default `LLM_MODEL` is `openai/gpt-4o-mini` via OpenRouter (`OPENAI_BASE_URL` default `https://openrouter.ai/api/v1`); credential name remains `OPENAI_API_KEY`.

## Voice onboarding (2026-09-28)

The `/start` and voice behavior above describes ordinary conversation. New users first receive the invitation and `Let’s chat 👋`. Existing users keep ordinary conversation; `/onboarding` explicitly starts/restarts the introduction. `/start` resets an incomplete introduction, but does not reset a completed one.

The introduction keeps correction quotes and English voice follow-ups. The first voice carries the reply hint as its caption. One button under the latest voice shows `m:ss / 2:00`, or `2:00+` once the introduction continues past two minutes. After each answer that button is removed from the previous voice and attached to the new one. Tapping it sends `🎙 This tracks how much English you've spoken. Around 2 minutes is usually enough for me to get to know you a little.` Speaky's voice messages also carry a `Subtitles` button on the same row as the clock. Tapping it sends the spoken line as a quote headed `💬 Speaky said:`. The line is kept in the bot process, so that button stops working after a restart. The first voice of an introduction gets a ❤ reaction; later voices in that attempt do not, except the last user voice, which gets 🔥. The closing Speaky voice shows `See my results` instead of the clock, beside `Subtitles`. The level message appears only after that tap. Its button is `See what I noticed →`. It collects work, free time, and why English, and a CEFR estimate that is shown in text after the close and never spoken. It closes after the recording that reaches or crosses 120 seconds of recognized speech, even when those fields are incomplete. There is no limit on the number of answers before that threshold. Missing fields do not delay completion. The last voice is a fixed warm goodbye, with one optional personal sentence when the transcripts contain a specific detail. The level message then edits in place through grammar, vocabulary, and fluency. Each of those scores is mapped in code from a band and a low/mid/high position, not chosen as a raw 0–100. A skill with no band shows `Not enough from this chat yet.` Overall CEFR is not the average of the three scores. Its own band and position become the headline score, with points to the next band when one exists. Confidence stays on the attempt and is not shown. `Continue →` asks for `☕ 5 min/day`, `✨ 10 min/day`, or `🔥 15 min/day`, each on its own row, and stores that choice outside the attempt. Those turns and the profile are then used in ordinary replies. `/onboarding` restarts the attempt while preserving durable personal memory, the last assessment and saved daily minutes.

Text answers are not analyzed. Before `Let’s chat 👋`, voice is not consumed. Failure to produce the final result offers `Retry` without requiring more speech. Button callbacks carry the attempt id and are acknowledged before waiting for AI. Actions for a chat are serialized through Telegram delivery, retaining the three-voice capacity.

Full decisions, timing semantics, persistence and acceptance checks: [onboarding plan](../plans/2026-09-28-telegram-onboarding.md).

### Level explanation (2026-09-29)

The review receives the overall CEFR and its low/mid/high position alongside transcripts, corrections, and fluency signals. `levelText` explains demonstrated English in two or three short sentences with one or two brief exact transcript excerpts when supported. It must not recap conversation topics or praise ideas/personality. Limitations require observed evidence; unused constructions are not weaknesses. Thin or mixed evidence is acknowledged rather than forced to fit the band. A null CEFR gets an explanation of insufficient evidence, without assigning a level. Band selection and score mapping are unchanged. Existing saved reviews are not regenerated.

### Compact assessment and conservative corrections (2026-09-29)

Grammar and Vocabulary use one diagnostic sentence (prompt limit: 25 words), a score, and zero to two examples. The report prompt is separate from the conversational voice persona. Examples have a `What I noticed` heading only when present; original text is struck through, replacement is bold on the following line. No empty-state claim of error-free speech is shown.

Before composing the review, AI-service checks that each candidate is a changed, exact whole phrase from its source transcript. A separate model call sees the original transcript and candidate pair and can return only existing candidate IDs. Its rule is: `If uncertain whether the user actually made the error, omit it.` It rejects ambiguous names, probable ASR artifacts, self-corrections, repetitions, contradictions, and changes that guess the intended meaning. Only accepted examples are ranked (repeats first, word before natural) and passed to the review. The model cannot insert new pairs. Verification errors, malformed/unknown IDs, or a 10-second timeout omit all examples without blocking the report. This is conservative transcript-based screening, not audio verification or a calibrated confidence score. Live turn correction cards and overall CEFR selection are unchanged.

Zero detected fillers become unknown (`null`) before review generation. Telegram also hides zero values from older reports; positive counts are labeled `Detected filler words`. ASR detections are not a complete count. The practice prompt includes the next band's low score, computed from the existing overall score plus `pointsToNext`; no duplicate score table is added. Older responses without that distance retain the band-only target. The practice question and buttons remain.

Completed reviews remain cached; the new selection and wording apply to newly generated reviews. The new Telegram rendering also applies when opening cached cards, but does not retroactively verify their examples. Verify live outputs before release; unit tests with fakes cannot establish the semantic accuracy of the model's screening.

## Progress overview

`/profile` shows the latest completed assessment, daily goal and current streak, with `🔥 View streak` opening the existing calendar. It is introduced by one line in the final daily-goal message, without an additional onboarding screen. The last assessment survives a new attempt.
