# Telegram bot behaviour

Library: `tgbotapi` (inmo). Webhook only in production (`TelegramWebhook.kt`). Header `X-Telegram-Bot-Api-Secret-Token` must equal `TELEGRAM_WEBHOOK_SECRET`. Valid update is queued, then **200**. Bad secret → **403**. A handler that drops the update after 200 is a permanent loss: Telegram will not retry.

Logs: `RedactingKSLog` strips bot token and `/bot<token>` URL fragments.

## Commands and messages (`TelegramHandlers.kt`)

- `/start`: any message whose first token is `/start`, including `/start@bot` and `/start payload`. `onCommand` alone drops a command that is not a single bot-command entity, and the text handler used to ignore every line starting with `/`, so that update got 200 and no reply. Greeting is sent with `allowSendingWithoutReply`. Log the Telegram message ids of the text and the voice. Then `ai.startSession(sessionId)` (POST session + greeting audio), text from `startTextMessage(firstName)`, then `sendVoice` greeting. Uses private-chat first name when present.
- `/streak`: same first-token rule, including `/streak@bot`. `setMyCommands` registers `start` and `streak` after the webhook is set. The reply is one photo of the rolling Moscow week (six days back through today, rightmost is today), with the current streak and a random short cheer as the caption. The card is a white rounded panel on cream `#FBFAF6`, in Inter. A practiced day is blue `#1874FC` with a white check and a glow, a missed day is a light circle with a gray cross, and today with no voice is an empty outline. The date range is that window, not a fixed string. A failure to load the profile replies with `ERROR_TEXT`. If the photo cannot be sent, only the caption goes out. Duplicate delivery from `onCommand` and the text handler is deduped by chat id and message id.
- **Voice**: `ensureSession` then queue. On complete, if the transcript is non-blank, `coachingEntities(transcript, corrections)`, then `sendVoice` reply OGG. The streak photo is not sent here; it is only the `/streak` command. Failures of the clip itself → `ERROR_TEXT`.
- Non-command **text** → `Please send a voice message.`
- Other content: ignore.

Queue copy:

- Behind others: `Got it — I'll answer in order.`
- Full: `Too many voice messages at once. Wait for my reply, then send again.`

Voice download is OGG (`voice.ogg`, `audio/ogg`).

## Coaching quote (`CoachingFeedback.kt`)

Input is `List<Correction>` (`speaking/ClipProcessor.kt`): `wrong`, `better`, `kind` (`GRAMMAR` / `WORD` / `NATURAL`, or `null`). `HttpClipClient` builds it from `result.corrections`; if that is empty it falls back to legacy `result.notes` (`wrong|||better`, `parseCorrections`) with `kind = null`.

Priority `grammar` > `word` > `natural` > no kind. At most **3** corrections: sorted by priority, then `take(3)`, so natural never pushes out grammar.

Telegram entities: line `🗣️ You said:` then a **blockquote**. Each matched `wrong` in the transcript gets, when `kind` is set, an *italic* Russian label on its own line above it (`StartMessage.kt`): `Грамматически верно:`, `Лучше подойдёт слово:`, `Нейтив сказал бы так:`. Then `wrong` in **strikethrough** on the next line, then **bold** `better` on the line after. Unmatched `wrong` is skipped. A match counts only as a whole word or phrase (letters/`'` on either side block it), so `me` does not cut `remember`. Overlapping spans: higher-priority kind wins; same kind → earlier start, then longer. Chosen spans are rendered in transcript order. Trailing `. ! ? , ;` after a span is kept with the span so it does not orphan on the next line.

If transcript is blank, **no** text quote is sent (voice still sent).

## LLM (`ai-service/app/llm.py`)

Two completions in `ClipPipeline` (`asyncio.gather`):

- **Reply** (`REPLY_SYSTEM`): JSON `{"reply"}` only. History included; `temperature` 0.7. Spoken turn is about three to six sentences: a specific reaction to what they just said, then one question that continues it. Same manner in onboarding and realtime (`app/voice.py`). No corrections in the reply.
- **Notes** (`NOTES_SYSTEM`): JSON `{"notes":[{"wrong","better","kind"}]}` or `[]`. Transcript only; `temperature` 0. `kind`: `grammar` (breaks grammar), `word` (grammatical, wrong word for the meaning / collocation), `natural` (grammatical, but a native would clearly not say it: calque, unidiomatic). A span with a grammar mistake is `grammar` even if it could also sound more natural. Spans must not overlap. Empty list only if already correct and natural. Few-shots teach span width (already fine; one word; short phrase; expand for a missing word; expand for an extra word; two holes) plus one `word` and one `natural` example.

`wrong` must be an exact contiguous whole-word substring of the transcript (Kotlin skips unmatched and in-word hits). `parse_corrections` returns `Correction(wrong, better, kind)`; unknown or missing `kind` → `grammar`; pre-joined `wrong|||better` strings are still accepted. Stable sort by priority, then max 3.

**Experiment (2026-09-25):** `natural` has no quota of its own; it only loses to grammar/word on priority and the shared max of 3. Risk against `product.md` («2–3 наиболее важных слабых места», not a style report): natural edits may flood the quote with fine-but-fancier rewrites. If natural dominates notes on DEV/prod, add a quota (e.g. natural only when there is no grammar note) instead of removing the kind. `max_completion_tokens` 500, `response_format=json_object`. Default model env `LLM_MODEL` = `openai/gpt-4o-mini` via OpenRouter (`OPENAI_BASE_URL` default `https://openrouter.ai/api/v1`). Key env name is still `OPENAI_API_KEY`.

## Voice onboarding (2026-09-28)

The `/start` and voice behavior above describes ordinary conversation. New users first receive the invitation and `Let’s chat 👋`. Existing users keep ordinary conversation; `/onboarding` explicitly starts/restarts the introduction. `/start` resets an incomplete introduction, but does not reset a completed one.

The introduction keeps correction quotes and English voice follow-ups. The first voice carries the reply hint as its caption. One inert button under the latest voice shows `🎙 m:ss / 2:00`, or `🎙 2:00+` once the introduction continues past two minutes. After each answer that button is removed from the previous voice and attached to the new one. Tapping it does nothing. Speaky's voice messages also carry a `Субтитры` button. Tapping it sends the spoken line as a quote headed `💬 Speaky said:`. The line is kept in the bot process, so that button stops working after a restart. The first voice of an introduction gets a ❤ reaction; later voices in that attempt do not. It collects work, free time, and why English, and a hidden CEFR estimate. It closes at 120 seconds of recognized speech once those three fields are filled, or at 10 recognized answers when the fields and a level are both known. Missing fields keep it going past 120 seconds. The closing turn is still a voice question, followed by `Я тебя запомнила. Давай просто говорить.` The level is not shown. Those turns and the profile are then used in ordinary replies. `/onboarding` wipes the profile until the next completion. A grammar, vocabulary, and fluency review is deferred.

Text answers are not analyzed. Before `Let’s chat 👋`, voice is not consumed. Failure to produce the final result offers `Повторить` without requiring more speech. Button callbacks carry the attempt id and are acknowledged before waiting for AI. Actions for a chat are serialized through Telegram delivery, retaining the three-voice capacity.

Full decisions, timing semantics, persistence and acceptance checks: [onboarding plan](../plans/2026-09-28-telegram-onboarding.md).
