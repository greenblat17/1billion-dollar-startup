# Telegram bot behaviour

Library: `tgbotapi` (inmo). Webhook only in production (`TelegramWebhook.kt`). Header `X-Telegram-Bot-Api-Secret-Token` must equal `TELEGRAM_WEBHOOK_SECRET`. Valid update → **200** immediately; work on webhook scope. Bad secret → **403**.

Logs: `RedactingKSLog` strips bot token and `/bot<token>` URL fragments.

## Commands and messages (`TelegramHandlers.kt`)

- `/start`: `ai.startSession(sessionId)` (POST session + greeting audio), text from `startTextMessage(firstName)`, then `sendVoice` greeting. Uses private-chat first name when present.
- **Voice**: `ensureSession` then queue. On complete: if transcript non-blank, reply with `coachingEntities(transcript, notes)`; always `sendVoice` reply OGG. Failures → `ERROR_TEXT`.
- Non-command **text** → `Please send a voice message.`
- Other content: ignore.

Queue copy:

- Behind others: `Got it — I'll answer in order.`
- Full: `Too many voice messages at once. Wait for my reply, then send again.`

Voice download is OGG (`voice.ogg`, `audio/ogg`).

## Coaching quote (`CoachingFeedback.kt`)

Separator `|||`. `parseCorrections` keeps only two non-empty sides. At most **3** notes used.

Telegram entities: line `🗣️ You said:` then a **blockquote**. Each matched `wrong` in the transcript is **strikethrough** + space + **bold** `better`. Unmatched `wrong` is skipped. Overlapping spans: first non-overlapping after sort by start, longer wins on same start. Trailing `. ! ? , ;` after a span is kept with the span so it does not orphan on the next line.

If transcript is blank, **no** text quote is sent (voice still sent).

## LLM (`ai-service/app/llm.py`)

Two completions in `ClipPipeline` (`asyncio.gather`):

- **Reply** (`REPLY_SYSTEM`): JSON `{"reply"}` only. Conversation partner; history included; `temperature` 0.7. No corrections in reply.
- **Notes** (`NOTES_SYSTEM`): JSON `{"notes":[{"wrong","better"}]}` or `[]`. Transcript only (no dialogue history); `temperature` 0. Grammar/lexis only — not style, fluency, or self-repair. Default empty list.

`wrong` must be an exact contiguous substring of the transcript (Kotlin skips unmatched). `better` is a drop-in for that span: prefix + better + suffix must read as one sentence (no leftover tail like `on the weekend` after replacing only `I walk`). If a short span cannot splice cleanly, expand `wrong` or omit the note. No extra Python splice filter.

Parser maps objects (or pre-joined strings) to `wrong|||better`. Max 3 notes. `max_completion_tokens` 500, `response_format=json_object`. Default model env `LLM_MODEL` = `openai/gpt-4o-mini` via OpenRouter (`OPENAI_BASE_URL` default `https://openrouter.ai/api/v1`). Key env name is still `OPENAI_API_KEY`.
