# Логи вызовов LLM, STT и TTS

Статус: реализовано в коде; выкат и проверка появления записей на DEV остаются отдельными действиями.

AI-сервис пишет одну строку `provider_call` в stdout для **каждой фактической попытки** HTTP-вызова LLM, STT или TTS. Если запрос повторён после ошибки, в журнале остаются обе попытки. Telegram API в этот журнал не входит. Записи уходят в существующий Loki через Alloy; отдельная база, счётчики и панель Grafana не добавляются.

В строке находится JSON с полями `timestamp` (UTC), `source` (`telegram`, `android`, `ios`, `desktop`, `load_test` или `unknown`), `user_id` (обезличенный), `type` (`llm`, `stt`, `tts`), `purpose` для LLM, `provider`, `model`, `result` (`success`, `error` или `cancelled`), `http_status`, `error_code`, `duration_ms` и `cost_micro_usd`. У HTTP-ошибки `http_status` содержит фактический статус. У успешного ответа OpenAI-совместимого SDK статус недоступен и поле равно `null`; успешный результат явно указан в `result`. При сетевой ошибке статуса тоже нет; `error_code` содержит тип исключения. `cost_micro_usd` заполняется для LLM из `usage.cost`; если провайдер не вернул стоимость, поле равно `null`, а не нулю. Стоимость STT и TTS здесь не рассчитывается.

`user_id` — первые 20 символов HMAC-SHA256 от нормализованного Telegram chat ID или ID пользователя приложения. Ключ — обязательный `AI_INTERNAL_TOKEN`, значение которого в лог не попадает. Сессии одного Telegram-чата или аккаунта приложения дают один псевдоним; при смене токена псевдоним меняется. Там, где вызов не связан с сессией (например, служебный прогрев), поле равно `null`. Платформа мобильной сессии берётся из уже сохранённой привязки, а для внутреннего запроса обзора передаётся вместе с ID сессии.

Запись не содержит исходный ID, аудио, текст реплики, запрос к модели, ответ или API-ключ. Прежние продуктовые агрегаты `metrics:*` и `metrics:v2:*` не меняются. Срок хранения Loki — 30 дней по действующей настройке. Старые записи не дополняются задним числом. Объединённый OpenAI Realtime вызов не раскладывается на отдельные STT/LLM/TTS попытки: эти внутренние операции провайдера не видны AI-сервису как отдельные HTTP-запросы.
