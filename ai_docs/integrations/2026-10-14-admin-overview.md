# Главная страница аналитики `/admin/metrics`

Статус: реализовано в коде; проверка PROD после выката проводится отдельно.

`/admin/metrics` — новая защищённая главная страница. Прежняя сводка доступна по `/admin/metrics/details`; страницы онбординга, звонков, ошибок, напоминаний и стриков сохраняют адреса и вход через `METRICS_PASSWORD`. Период — от 1 до 30 московских суток, включая границы; по умолчанию последние семь календарных дней вместе с текущим незавершённым днём. CMP собирает итоговый HTML на сервере. Браузер не обращается напрямую к Redis или PostgreSQL.

## Определения

| Показатель | Источник и расчёт |
| --- | --- |
| Всего чатов | Объединение Telegram session ID из старой воронки `metrics:funnel:user:*` и нового учёта голосовых `metrics:v2:telegram:journey:user:*` в Redis. Это известные боту чаты, а не зарегистрированные аккаунты таблицы `users`. |
| Рост числа чатов | Для каждого чата в старой воронке Redis берётся `first_day`; график показывает накопленное число таких Telegram-чатов на конец каждого выбранного дня, включая чаты, пришедшие до начала выбранного периода. Чаты без даты первого обращения не включаются в линию, их число показывается отдельно. |
| DAU по Redis | Ежедневное число уникальных Telegram-чатов из `metrics:dau:YYYY-MM-DD`: у них завершился хотя бы один ход AI за день. Ряд охватывает сохранённую историю по обе стороны 6 октября. Это иное определение, чем «Активные за период и по дням» ниже. |
| Активные за период и по дням | Уникальные `chat_id` с входящим событием `voice`, `text` или `callback` со статусом `received` в `interaction_events`. Для карточки за период считаются уникальные чаты за весь период, не сумма DAU. |
| Голосовые | Строки `telegram_voice_attempts` по `received_at`; уникальность пары чат + ID сообщения обеспечивает БД. Включены все входящие голосовые, даже если обработка не удалась. |
| Успешные обмены | Голосовая попытка с `outcome='delivered'` и записью непустой транскрипции `interaction_events` (`kind='transcript'`, `status='ready'`) для того же `attempt_id`. Подтверждает отправленное ГС и доставленный голосовой ответ; если запись транскрипции в аудит не удалась, число будет ниже фактического. |
| LLM / STT / TTS | Успешно учтённые вызовы Telegram в `metrics:v2:day:YYYY-MM-DD:telegram` Redis. Помеченные нагрузочные тесты исключены; ошибки и внутренние повторы SDK в старых суточных счётчиках могут отсутствовать. |
| Telegram API | Попытки исходящих `send*`, `edit*`, `deleteMessage`, `setMessageReaction` в `interaction_events`, у которых есть `attempt_id` входящего сообщения. Это пользовательский сценарий; фоновые рассылки и методы вроде `getFile` или `sendChatAction` в исторический счёт не входят. |
| Вызовов / активный чат | Сумма четырёх предыдущих компонентов за период / уникальные активные чаты за тот же период. Помечено как неполный показатель. Если хотя бы один источник не покрывает весь период, значение не показывается. Отдельные навыки и внутренние сервисные вызовы не считаются без события выполнения. |
| LLM-cost / обмен | Известная сумма `usage.cost` фактических LLM-попыток при обработке Telegram-голосовых / успешные обмены за тот же период. Новое дневное поле `voice_llm` сохраняется в Redis при завершении голосовой задачи. Дата первого такого поля фиксируется отдельно; до неё показатель не рассчитывается. Если цена провайдером не возвращена, стоимость является нижней границей, а не нулевой. |
| Ошибки | Терминальные голосовые попытки с `eligible=true`, `outcome` не `delivered` и не `not_eligible`. Незавершённые попытки не записываются как ошибки. |

AI предоставляет CMP защищённый `GET /internal/metrics/overview?from=YYYY-MM-DD&to=YYYY-MM-DD`: число известных Telegram-чатов, ежедневные вызовы моделей и известную стоимость LLM. CMP читает продуктовые события из PostgreSQL. Главная страница не обращается к Loki; ошибки голосового пути берутся из PostgreSQL.

Исходные события PostgreSQL и дневные записи Redis хранятся 30 дней. Более ранние точки на графиках не дорисовываются нулями. У каждого источника показывается первая доступная дата; карточка отношения скрывается, если данные не покрывают весь выбранный период. Прометей сохраняет ряд скрейпов до 185 дней, но этот первый выпуск страницы рассчитывает продуктовые метрики по исходным PostgreSQL/Redis данным и ограничивает выбор 30 днями.

Первый день каждого источника может начаться после полуночи. Его значения видны в таблице, но итоговые карточки с отношениями рассчитываются только для периода, начинающегося на следующий день или позже. Особенно это важно для нового учёта цены LLM при голосовых: день первого измеренного обращения не даёт полной стоимости всех обменов за сутки.

## Старые данные до 6 октября

В Redis PROD сохранились дневные ключи старого учёта `metrics:day:YYYY-MM-DD`, наборы `metrics:dau:YYYY-MM-DD` и воронка `metrics:funnel:YYYY-MM-DD`, начиная с 24 сентября 2026 года. Главная страница показывает два графика по Redis за всю выбранную часть этой истории: накопленное число чатов по `first_day` и DAU по дневным наборам `metrics:dau`. Эти наборы продолжают заполняться после 6 октября. При выборе дат до 6 октября страница дополнительно показывает: чаты с завершённым ходом AI, число таких ходов, входные и выходные токены LLM, длительность STT, символы TTS и число чатов, впервые отправивших голосовое. Для исторической части периода уникальные Telegram-чаты берутся из объединения дневных наборов `metrics:dau`.

Эти показатели нельзя незаметно подставить в новые карточки: `metrics:dau` пополнялся после завершения хода AI, а новая «активность» учитывает любое входящее голосовое, текст и кнопку; старый ход AI происходил до фактической доставки голоса пользователю; `activated` означает только **первое** голосовое чата. Старый дневной счётчик также не разделяет токены и ходы по платформе. Поэтому точное число всех входящих голосовых, доставленных ответов, вызовов LLM/STT/TTS/Telegram API и стоимость LLM до 6 октября остаются неизвестными. Соответствующие новые карточки продолжают показывать «—».

На текущем PROD таблицы PostgreSQL `interaction_events`, `telegram_voice_attempts`, `onboarding_entries`, `onboarding_attempts`, `onboarding_voices` и `telegram_call_events` не содержат строк до 6 октября. Данные раннего периода для этой страницы находятся в старом Redis, а не в этих таблицах.

График стоимости показывает известные расходы на все LLM-вызовы и отдельно на голосовые обращения. После первой доступной даты модельных измерений день без записанных вызовов показывается нулём. Цена вызова может отсутствовать; поэтому стоимость за день и за обмен является нижней границей при неполном покрытии цен.
