# Переменные окружения Speaky

Файл для агента, которому нужно понять, где лежит настройка и какого она вида. Здесь имена, роль и вид значения. Сами секреты, пароли, токены и строки `GROQ_BASE_URL` / `OPENAI_BASE_URL` с хостов сюда не копируются.

Шаблон имён: [`.env.example`](../../.env.example). Чтение в коде: `cmp/server/.../AppConfig.kt` и `ai-service/app/config.py`. Выкат: `.github/workflows/deploy-cmp-server.yml`, `deploy-ai-server.yml`.

Срез «ключ есть на диске» снят 11 октября 2026 по именам уже разложенных файлов. Тела файлов не печатались.

## Как это упаковано

На VPS два разных файла, не один общий:

| Файл на хосте | Откуда берётся при Redeploy |
| --- | --- |
| `/opt/speaking-coach/.env` | целиком из `DEV_CMP_SERVER_ENV` или `PROD_CMP_SERVER_ENV` |
| `/opt/ai-service/.env` | целиком из `DEV_AI_SERVER_ENV` или `PROD_AI_SERVER_ENV` |

Секреты GitHub — repository Actions secrets, не Environment secrets. Отдельных ячеек `GROQ_API_KEY` или `TELEGRAM_BOT_TOKEN` в Actions нет: эти ключи живут внутри блоба. Исключение — `METRICS_PASSWORD`: это отдельная ячейка, и выкат CMP вырезает такую строку из блоба и дописывает значение из ячейки.

`AI_INTERNAL_TOKEN` по контракту выката один и тот же в блобе CMP и в блобе AI. 11 октября ключ был на всех четырёх файлах. Строки между собой не сравнивались.

## CMP: `/opt/speaking-coach/.env`

Пустая строка для процесса равна отсутствию ключа.

| Ключ | Что задаёт | Что в значении | Если ключа нет | DEV | PROD |
| --- | --- | --- | --- | --- | --- |
| `TELEGRAM_BOT_TOKEN` | бот и вебхук | токен BotFather | вебхук не поднимается | да | да |
| `TELEGRAM_WEBHOOK_URL` | режим вебхука | публичный HTTPS URL, который зовёт Telegram | режим без вебхука | да | да |
| `TELEGRAM_WEBHOOK_SECRET` | проверка заголовка и `setWebhook` | общий секрет с Telegram | при заданном URL процесс не стартует | да | да |
| `AI_SERVICE_BASE_URL` | куда Ktor шлёт клипы | URL ai-service | `http://127.0.0.1:8090` | да | да |
| `AI_INTERNAL_TOKEN` | заголовок `X-Internal-Token` на `/v1/*` и `/internal/*` | общий секрет с AI-хостом | при вебхуке процесс не стартует | да | да |
| `SERVER_PORT` | порт Ktor; выкат требует число | номер порта | `8080`; скрипт мониторинга подставляет `443` | да | да |
| `TLS_CERT_PATH` | сертификат вебхука | путь к PEM на хосте | `/opt/speaking-coach/tls.crt` | да | да |
| `TLS_KEY_PATH` | ключ вебхука | путь к PEM на хосте | `/opt/speaking-coach/tls.key` | да | да |
| `JWT_SECRET` | HMAC Bearer для CMP-клиента | секрет подписи | маршруты `/v1/auth` не ставятся | да | да |
| `DATABASE_URL` | пользователи, сессии, журнал в Postgres | JDBC URL, пароль базы внутри строки | при токене бота процесс не стартует | да | да |
| `POSTGRES_USER` | роль при первом создании контейнера Postgres | имя роли | скрипт берёт `speaking` | да | да |
| `POSTGRES_PASSWORD` | пароль той роли | пароль | скрипт не создаёт контейнер Postgres | да | да |
| `POSTGRES_DB` | имя базы при создании контейнера | имя базы | скрипт берёт `speaking_coach` | да | да |
| `GRAFANA_ADMIN_PASSWORD` | пароль Grafana | пароль | Grafana не публикуется | да | нет |
| `GRAFANA_ROOT_URL` | `GF_SERVER_ROOT_URL` | публичный origin, вид `https://хост:8443` | скрипт подставляет `https://127.0.0.1:8443` | да | нет |
| `MONITORING_PORT` | localhost-порт `/admin/monitoring` | номер порта | `8081`; публичный TLS этот путь не отдаёт | да | нет |
| `METRICS_PASSWORD` | вход на `/admin/metrics` | пароль; на диске побеждает ячейка GitHub | страница выключена | да | да |
| `AUDIT_AUDIO_DIR` | каталог голоса человека и ответа модели | путь на хосте | `/opt/speaking-coach/audit-audio` | нет | нет |
| `SPEAKY_ENV` | метка среды в мониторинге | короткое имя, например `dev` или `prod` | скрипт пишет `unknown` | нет | нет |

`POSTGRES_*` читают скрипты `infra/postgres/deploy-remote.sh` и `infra/backup/backup-remote.sh`. Ktor ходит в базу по `DATABASE_URL`.

Токен бота требует `TELEGRAM_WEBHOOK_URL` и `DATABASE_URL`. URL вебхука требует `TELEGRAM_WEBHOOK_SECRET` и `AI_INTERNAL_TOKEN`.

## AI: `/opt/ai-service/.env`

Старт ai-service требует `GROQ_API_KEY`, `OPENAI_API_KEY` и `AI_INTERNAL_TOKEN`. `TTS_PROVIDER` бывает только `openrouter` или `deepgram`.

| Ключ | Что задаёт | Что в значении | Если ключа нет | DEV | PROD |
| --- | --- | --- | --- | --- | --- |
| `GROQ_API_KEY` | Whisper STT | ключ Groq | процесс не стартует | да | да |
| `GROQ_BASE_URL` | адрес STT | базовый URL OpenAI-совместимого API | `https://api.groq.com/openai/v1` | да | да |
| `STT_MODEL` | модель распознавания | id модели | `whisper-large-v3` | да, `whisper-large-v3` | нет |
| `OPENAI_API_KEY` | чаты и TTS через OpenRouter | ключ OpenRouter; имя историческое | процесс не стартует | да | да |
| `OPENAI_BASE_URL` | адрес чатов и TTS | базовый URL | `https://openrouter.ai/api/v1` | да | да |
| `LLM_MODEL` | голосовой ответ | id модели OpenRouter | `openai/gpt-5.6-luna` | да, `openai/gpt-5.6-luna` | да, `openai/gpt-5.6-luna` |
| `NOTES_MODEL` | живые поправки | id модели | `openai/gpt-5.6-luna` | да, `openai/gpt-5.6-luna` | нет |
| `ONBOARDING_REVIEW_MODEL` | оценка онбординга | id модели | берётся `LLM_MODEL` | да | да |
| `ONBOARDING_REVIEW_FALLBACK_MODEL` | вторая попытка оценки, если первая не разобралась | id модели | повтор идёт той же моделью, с большим потолком токенов | да | да |
| `TTS_PROVIDER` | кто озвучивает ответ | `openrouter` или `deepgram` | `openrouter` | да, `openrouter` | нет |
| `TTS_MODEL` | модель озвучки OpenRouter | id модели | код подставляет `hexgrad/kokoro-82m` | да, `x-ai/grok-voice-tts-1.0` | да, `x-ai/grok-voice-tts-1.0` |
| `TTS_VOICE` | голос OpenRouter | имя голоса | `af_heart` | да | да |
| `TTS_RESPONSE_FORMAT` | формат ответа OpenRouter до ffmpeg | `mp3` и затем OGG | `mp3` | да | да |
| `TTS_OUTPUT_FORMAT` | формат прямого Deepgram | `ogg` или `mp3` | `ogg` | да | нет |
| `TTS_SPEED` | скорость Aura-2; OpenRouter это поле игнорирует | число от 0.7 до 1.5 с шагом 0.05 | `0.9` | да | нет |
| `DEEPGRAM_API_KEY` | прямой TTS Deepgram | ключ Deepgram | нужен только при `TTS_PROVIDER=deepgram` | да | нет |
| `FFMPEG_BIN` | перекодирование в OGG | имя или путь бинарника | `ffmpeg` | да | нет |
| `REDIS_URL` | диалог, метрики, звонки | URL Redis; пароль, если есть, внутри строки | память процесса, без Redis | да | да |
| `AI_INTERNAL_TOKEN` | проверка `X-Internal-Token` | тот же секрет, что на CMP | процесс не стартует | да | да |
| `AI_SERVICE_PORT` | порт, который скрипт публикует с хоста | номер порта; внутри контейнера остаётся 8090 | скрипт берёт `8090` | да | да |
| `OPENAI_REALTIME_API_KEY` | WebRTC mint и наблюдение звонка CMP | ключ platform.openai.com | realtime-маршруты выключены; голосовой ход Telegram от этого не зависит | да | да |
| `DIALOGUE_TTL_SECONDS` | срок ключа диалога | секунды | `2592000` (30 суток) | нет | нет |
| `DIALOGUE_MAX_MESSAGES` | сколько реплик держать в диалоге | число | `40` | нет | нет |
| `JOB_TTL_SECONDS` | срок задания клипа в памяти процесса | секунды | `600` | нет | нет |
| `PIPELINE_TIMEOUT_SECONDS` | потолок всего клипа | секунды | `60` | нет | нет |
| `LOG_LEVEL` | уровень логов процесса | имя уровня | `INFO` | нет | нет |
| `LOKI_PUSH_URL` | выгрузка логов AI в Loki | HTTPS URL push | `infra/ai-service/deploy-alloy.sh` пропускает выгрузку | нет | нет |
| `SPEAKY_ENV` | метка `environment` у Alloy | короткое имя среды | скрипт пишет `unknown` | нет | нет |

`AI_SERVICE_PORT` читает `infra/ai-service/ai-service-port.sh`, не `Settings`. `LOKI_PUSH_URL` и `SPEAKY_ENV` читает `deploy-alloy.sh`.

`TTS_PROVIDER` на обоих хостах в итоге `openrouter`: на PROD ключа нет, и срабатывает дефолт. `DEEPGRAM_API_KEY` есть только на DEV и в этом режиме не используется. Живая озвучка — `x-ai/grok-voice-tts-1.0`, это не дефолт кода `hexgrad/kokoro-82m`.

Значения `ONBOARDING_REVIEW_MODEL`, `ONBOARDING_REVIEW_FALLBACK_MODEL`, `TTS_VOICE`, `TTS_RESPONSE_FORMAT` и номера `AI_SERVICE_PORT` на диске заданы, но в этот файл не переносились.

## Не в этих блобах

| Имя | Где живёт | Что в значении |
| --- | --- | --- |
| `SPEAKING_COACH_API_BASE_URL` | клиент CMP: env или `cmp/client.local.properties` (`speakingCoach.apiBaseUrl`) | базовый URL Ktor; CI подставляет `https://` и хост из `DEV_CMP_SERVER_HOST` / `PROD_CMP_SERVER_HOST` |
| `TEST_POSTGRES_URL` | только локальные тесты Ktor | JDBC URL тестовой базы; пусто — тест пропускается |
| `cmp` файл `8090.allow` | `/opt/ai-service/8090.allow`, не ключ `.env` | список адресов, которым скрипт оставляет доступ к опубликованному порту AI |
