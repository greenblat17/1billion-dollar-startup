# SP-12B — Pedagogical Logic (утверждённый план)

Дата: 2026-11-17. Статус: **утверждён пользователем; локальная реализация в отдельной ветке**.
База: `origin/bb/sp-02-05-v5-5`, `2487b22`, draft PR #58. Отдельная ветка: `bb/sp-12b-pedagogical-logic-thr_fi3xp7cvaj`.

## 1. Результат для ученика

Для одной Learning Task репетитор применяет утверждённый шаблон обучения. Ученик, который не знает конструкцию, получает объяснение и практику. Ученик, который знает правило, но ошибается, сразу практикует применение. Активные Grammar/Vocabulary проверяются в разговоре; Listening и пассивный Vocabulary — на понимание. При отказе от задания урок может продолжиться вне текущей Task; её этап и прогресс сохраняются.

## 2. Вход и выход

- Вход текущего базового выбора: принадлежащая ученику SP-04 Task с `goal`, `skillId`, `topicId`, `problemId`, `catalogVersion`, `details.plan`, revision и точные записи SP-02 каталога. Доступное SP-03 учебное состояние и SP-17 Observations понадобятся при будущей контекстной адаптации; текущие шесть шаблонов не делают из них новых методов или весов. Для перехода требуется готовый SP-19 Stage Score либо подтверждённое binary requirement.
- Unknown/нехватка evidence не приравниваются к `Not Known`. Уровень, самооценка и целевой результат влияют на педагогическое решение лишь если реально известны. Нельзя сочинять Topic/Problem ID. По решению SP-17B, Trial не оценивает Listening: системный Listening CEFR после него остаётся Unknown, self-report хранится отдельно. Trial Listening Observation не является входом SP-12B для выбора или адаптации Plan.
- Выход: валидная SP-12A `definition` (методы, kind, веса, order, transitions), первый `currentStageId` и объяснимое основание выбора отдельно от definition. Запись идёт через `create_learning_plan`; `revise_learning_plan` разрешён только между уроками при наличии нового утверждённого шаблона. `select_learning_stage` используют только для планового перехода/возврата, не для пропуска по просьбе ученика.
- Для SP-13A передаётся точный `StageRef={taskId,planId,planRevision,stageId}`, method и Task/Topic/Problem context. SP-13A определяет формат и материал Teaching Action, включая допустимые ответы и дефекты, но не выбирает состав Plan.
- Для SP-19 доступны неизменяемые binary/numeric definitions и веса. SP-12B не меняет Score, Progress, binary completion или stage attempts.

## 3. Педагогическое правило

Сначала проверить связь Task с каталогом и смысл Topic objective/scope. Затем выбрать утверждённый базовый шаблон по Skill+Problem из четырёх методов: `Explanation`, `Exercises`, `Conversation`, `Exposure`. Topic определяет предмет работы и помогает выявить контекст, для которого базовый шаблон не подходит. Один Stage на метод, ненужный метод отсутствует. LLM не придумывает сочетания или веса. При отсутствии подходящего шаблона Task остаётся без Plan; пробел идёт в отдельную задачу.

Утверждённые в интервью базовые шаблоны для всех шести MVP Problem Types; 30/70 — временная конфигурация пары numeric этапов:

| Task / Problem | Ожидаемый Plan | Проверяемый смысл |
| --- | --- | --- |
| Grammar `grammar_unknown` | Explanation binary → Exercises 30% → Conversation 70% | Понять конструкцию, применить её, перенести в речь. |
| Grammar `grammar_application` | Exercises 30% → Conversation 70% | Закрепить правило без обязательного объяснения с нуля. |
| Speaking `speaking_barrier` | Conversation 100% | Самостоятельная речь — основная проверка. |
| Listening `listening_comprehension` | Exposure 100% | Последующее обучение на аудиофрагментах и проверка понимания; не оценка Listening на Trial. |
| Vocabulary `vocabulary_passive` | Exercises 100% | Узнавание и понимание, без обязательного произнесения в разговоре. |
| Vocabulary `vocabulary_active` | Exercises 30% → Conversation 70% | Извлечение слова и перенос в самостоятельную речь. |

Эти шесть строк — базовые шаблоны, не полная матрица для каждого Topic/CEFR и индивидуальной цели. Состав Speaking/Listening/Vocabulary и временные веса утверждены пользователем в интервью, а не выведены из фиксированной матрицы v5.5. При одном numeric Stage вес 100%. Reading/Writing вне MVP. Контекстные исключения и педагогическая проверка шаблонов вынесены в [будущую задачу Notion](https://app.notion.com/p/41a045c3d5768171a550e644146167a2).

`Explanation` может быть binary `understanding_demonstrated` и не получает процент. Подтверждение одним «ага» не доказывает понимания. Numeric weights неотрицательны и в сумме равны 1. Стартовый `S=50` не даёт Task Progress; формулы принадлежат SP-19. План с одними binary stages структурно допустим в SP-12A, но SP-12B не должен выдавать его без отдельного педагогического решения о завершении Task.

## 4. Адаптация и поведение в уроке

План задаёт order и допустимые переходы, включая возврат. Плановый переход вперёд происходит после выполнения binary requirement или при numeric `S≥85`; `S≤15` — сигнал пересмотреть действие и при необходимости вернуться, а не автоматический сброс. Разовый вопрос получает ответ сразу. Просьба ученика сменить формат не перескакивает через обязательный Stage. При отказе репетитор без давления выясняет причину и может продолжить беседу вне Task; cursor, Score и Progress этой Task не меняются. Смена темы относится к SP-09/16. Будущая возможность перехода по просьбе ученика записана [отдельной задачей Notion](https://app.notion.com/p/41a045c3d576816abb4ff4f84b0405eb).

SP-12B не вычисляет `S` и Task Progress. Например, при весах 30/70 отказ от Exercises оставляет оба Score прежними; даже пройденная Conversation даёт не больше 70%, пока Exercises не пройдены. Одна ошибка не переоткрывает завершённый Stage. Повтор действия и переход cursor не создают новую score attempt. Состав и веса Plan пересматриваются только между уроками. Существенная смена требует новой definition revision; прежний `StageRef` сохраняет исторический смысл. Перенос или сброс результатов при новой revision — решение SP-19/20.

При отсутствии подходящего шаблона вернуть явный результат без создания Plan и указать пробел для будущей задачи; никакого fallback.

5. Предоставить стабильный выходной интерфейс SP-13A/14/15 и будущему SP-19 без импорта соседних веток. Никаких новых native tools, UI или прямого подключения к живому звонку в этой подзадаче, пока SP-16 не готов.
6. Точечно обновить `ai_docs/integrations/learning-plan.md`, `architecture.md`, `ai_docs/README.md`, `ai_docs/status.md` после фактической реализации. В status отдельно указать локальные проверки, неготовые интеграции, DEV и live acceptance.

## 6. Проверка и приёмка

- Разные планы для `grammar_unknown` и `grammar_application` при одном Topic; Explanation не создаёт процентов.
- Активные Grammar/Vocabulary имеют путь к Conversation там, где это соответствует цели; Listening/пассивный Vocabulary проверяют понимание без обязательной говорильной проверки.
- Неизвестный уровень, противоречивый Problem/Skill, неподтверждённый каталог и неутверждённый сценарий обрабатываются явно; нет вымышленных ID или веса. Trial без Listening assessment оставляет системный Listening CEFR Unknown и не создаёт Listening Plan сам по себе.
- Plan сохраняется с Task через Python → Ktor → PostgreSQL; после revision старые StageRef разрешаются, Task Skill/Topic/Problem и Progress не меняются.
- Плановый переход и возврат не сбрасывают завершённый Stage. Student request не пропускает обязательный Stage; отказ не меняет cursor/Score/Progress, беседа вне Task допустима. Необязательный метод отсутствует, а не помечается failed.
- Ошибки в сумме весов, дубли методов, недопустимые transition/Stage identity и stale revisions отклоняются без частичной записи.
- Отдельно проверить контракт передачи StageRef/method в fixture SP-13A и definitions в fixture SP-19. Реальная цепочка с SP-13B/14/15/16/19B остаётся будущей интеграционной приёмкой.
- Запустить релевантные Python и Kotlin tests, HTTP/PostgreSQL integration при изменении контрактов, `git diff --check`. Не считать зелёные тесты подтверждением качества живого диалога.

8. При неполном или противоречивом Skill/Topic/Problem не создавать Plan и вернуть явную причину. Вопрос вне текущей Task обрабатывает урок, не Plan.
