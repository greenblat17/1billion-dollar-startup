# Telegram: постоянная кнопка Start call

Статус: реализовано в `feature/telegram-start-call`, ответвлена от `feature/telegram-onboarding` на `bfa5025`; локальная проверка выполнена, DEV Telegram ещё не проверен.

## Сценарий

После выбора дневной цели показывать в личном чате постоянную нижнюю Telegram reply keyboard с одной кнопкой `🎙 Start call`. Существующие inline-кнопки онбординга и разбора сохраняются: reply keyboard приходит отдельным коротким сообщением. У вернувшегося пользователя с завершённым онбордингом и сохранённой целью она также появляется после `/start`. При повторном `/onboarding` нижняя кнопка убирается. Нажатие отправляет в чат текст кнопки — так работает reply keyboard Telegram.

После нажатия бот проверяет тот же `callGate`, что и прямое голосовое: незавершённый онбординг остаётся в онбординге, отсутствующая оценка ведёт в `/onboarding`, отсутствующая цель — к существующему выбору 5/10/15 минут. Для готового пользователя AI-service открывает или находит practice call и готовит одно короткое английское голосовое сообщение Speaky с одним вопросом. Деталь из памяти/последнего разговора используется только когда она уместна; новых биографических фактов модель не придумывает. Следующий голосовой ответ пользователя идёт по существующему clip-пути. Время цели считает только распознанную речь пользователя. Прямое голосовое без кнопки по-прежнему начинает call.

После успешного начала разговора нижняя кнопка скрывается отдельным коротким сообщением с `ReplyKeyboardRemove`; первое голосовое Speaky по-прежнему несёт inline-кнопки часов, субтитров и завершения. Прямой голосовой вход скрывает нижнюю кнопку только после успешной обработки первого сообщения; после обновления бота это также срабатывает для уже открытого разговора, если у процесса ещё нет показанного call-сообщения. Повторное нажатие при уже начатом разговоре не создаёт новый call и не повторяет вступление: бот просит ответить голосом и убирает старую клавиатуру. Повторная доставка одного сообщения также не дублирует голосовое. После `End conversation` бот возвращает нижнюю кнопку отдельным сообщением. `/start` во время текущего call не показывает её снова.

## Реализация

1. Ktor: добавить reply keyboard и распознавать точный текст `🎙 Start call` до ветки напоминания/произвольного текста. Сериализовать действие через существующий `TelegramChatActions`. Показать keyboard после сохранения цели и при `/start` у готового пользователя; при принудительном онбординге и при начале call убрать через `ReplyKeyboardRemove`, после завершения вернуть. Для прямого голоса ответ `/internal/calls/open` сообщает `alreadyActive`; `/internal/calls/status` позволяет `/start` проверить текущий call без открытия нового.
2. AI-service: добавить внутреннее действие старта call с одним новым LLM-вызовом для вопроса и одним TTS-вызовом. Повторно использовать `CallStore.open`, персональный контекст, историю диалога и текущую настройку скорости голоса. Хранить вопрос и факт успешной отправки в `call:{id}`; повторный запрос до подтверждения отдаёт тот же вопрос, а после подтверждения не генерирует его заново. Отправленный вопрос записывать в историю диалога, чтобы ответ пользователя понимался в контексте. Отказ генерации или TTS допускает повторное нажатие без второй записи call.
3. Внутренний ответ старта передаёт текст, звук и сводку call; Ktor отправляет голосовое с текущими inline-кнопками часов, субтитров и завершения и подтверждает доставку только после успешного `sendVoice`. Старый путь `/internal/calls/open` для прямого голосового сохраняется.

## Проверка

Обновление: при запуске кнопкой сразу показываем `Speaky is joining the chat… 💙`, пока готовится голосовое; это сообщение также убирает нижнюю клавиатуру. Активный разговор проверяем до показа сообщения, ошибка генерации возвращает кнопку с предложением повторить. После `End conversation` постоянная кнопка возвращается на сообщении ожидания разбора, которое остаётся в чате. Временное сообщение `💙` с клавиатурой удалено из реализации: после его удаления кнопка исчезала в Telegram. Финальная карточка разбора больше не показывает inline-кнопки `Profile` и `Finish for today`.

Обновление 2026-10-01: финальное сообщение после выбора цели предлагает нажать `🎙 Start call` или отправить голосовое; практику можно начать сразу. Стартовое голосовое начинается с `Hi, <имя>! How are you?` при доступном имени Telegram, иначе с `Hi! How are you?`, затем задаёт вопрос по подтверждённой теме прошлого разговора, если такая тема есть. Формулировка напоминания варьируется естественно и не приписывает пользователю вымышленные события. Сообщение `Your turn—send a voice message.` с `ReplyKeyboardRemove` остаётся в чате; фразы `Let's talk.` и `Tap 🎙 Start call whenever you're ready. I'll go first.` больше не показываются. Расширение аудиофайла соответствует `audioContentType`. Форму волн и поведение клавиатуры после удаления сообщения нужно проверить в DEV Telegram.

- AI-service: первый/повторный старт, сохранение в Redis, переход на следующий московский день, сбой LLM/TTS и повторная попытка, подтверждение доставки, отсутствие начисленных секунд до речи пользователя.
- Ktor: постоянная клавиатура, распознавание точной кнопки до напоминаний, gate-состояния, повторное нажатие, один отправленный голосовой вопрос с call keyboard и субтитрами, прямое голосовое без кнопки.
- Запустить AI-service pytest и `./gradlew :server:test` из `cmp/`. Затем проверить в DEV Telegram на телефоне вид нижней клавиатуры, первый звук, повторный тап, `/onboarding`, `/start` и продолжение голосом. Локальные тесты не заменяют эту проверку.

Дополнительные LLM и TTS вызовы происходят только при нажатии кнопки для нового разговора. Измерить задержку от нажатия до первого голосового; пользовательский clip-путь не получает нового вызова.
