# MVP Development Plan

## Цель MVP

За четыре недели реализовать и подготовить к пользовательскому тестированию основную продуктовую
механику Speaking Coach:

```text
разговор → анализ → 2–3 слабых места → работа над ними → адаптированный следующий разговор
```

Главная проверяемая гипотеза: AI может использовать разговор не только как самостоятельную
практику, но и как диагностический механизм для персонального обучения пользователя.

## Принципы MVP

- Основной пользовательский интерфейс — разговор, а не набор упражнений.
- После сессии пользователь получает только 2–3 наиболее важных зоны роста.
- Каждый вывод должен быть подкреплён примером из реального разговора.
- Следующий диалог должен учитывать предыдущие ошибки и прогресс пользователя.
- Внешние STT, LLM, TTS и pronunciation assessment API используются там, где это сокращает срок
  разработки.


## Неделя 1 — Telegram-прототип и технический фундамент

### Задачи

- Реализовать короткий onboarding в Telegram.
- Принимать voice message пользователя.
- Создавать пользователя и speaking-сессию на backend.
- Определить единый контракт взаимодействия между backend и ML API.
- Реализовать в ML-компоненте pipeline `STT → LLM → TTS`.
- Передавать voice или text в ML API и получать transcript, ответ AI и результаты обработки.
- Сохранять аудио, transcript, реплики и связь с speaking-сессией.
- Отправлять пользователю голосовой ответ AI.
- Добавить статусы обработки, таймауты, повторные запросы и понятную обработку ошибок.
- Логировать время выполнения каждого этапа pipeline.

### Результат недели

Пользователь проходит onboarding и может провести в Telegram короткий последовательный голосовой
диалог с AI. Все реплики и transcript сохраняются в рамках speaking-сессии.

## Неделя 2 — Разговор в мобильном приложении

### Задачи

- Реализовать минимальный мобильный клиент для Android и iOS.
- Создать основной экран разговора (имитация Zoom-разговора).
- Реализовать запись и воспроизведение аудио.
- Автоматически определять окончание реплики пользователя.
- Реализовать последовательный voice-to-voice диалог без кнопок:
  пользователь говорит, AI обрабатывает реплику и отвечает голосом, после чего приложение снова
  начинает слушать пользователя.
- Интегрировать мобильное приложение с backend и ML API.
- Сохранять историю мобильной speaking-сессии.
- Реализовать базовый анализ Grammar и Vocabulary по transcript.

### Результат недели

Пользователь может провести голосовую speaking-сессию в мобильном приложении без ручной отправки
каждой реплики. Диалог сохраняется и передаётся на базовый анализ.

## Неделя 3 — Анализ речи и персонализация

### Задачи

- Реализовать анализ Grammar, Vocabulary и Fluency.
- Рассчитывать Speed of Speech как измеримую часть Fluency.
- Добавить базовую оценку Pronunciation через готовый специализированный API, если результаты
  проверки его качества приемлемы.
- Выбирать 2–3 наиболее важные слабые стороны по итогам сессии.
- Показывать пользователю экран результатов с:
  - описанием слабого места;
  - примером из разговора;
  - исправленным или улучшенным вариантом;
  - краткой рекомендацией.
- Формировать накопленный профиль пользователя на основе завершённых сессий.
- Адаптировать тему, сложность и поведение AI в следующем разговоре.
- Реализовать onboarding в мобильном приложении с фиксацией цели и первоначального уровня
  пользователя.

### Результат недели

Работает основной product loop: после разговора пользователь получает конкретный разбор, а следующая
сессия адаптируется под обнаруженные слабые места и накопленный прогресс.

## Неделя 4 — Индивидуальные задания, качество и пилот

### Задачи

- Генерировать короткие индивидуальные задания из реальных ошибок пользователя.
- Формировать тематические материалы для следующей практики.
- Отслеживать изменение ключевых показателей между speaking-сессиями.
- Полноценный duplex voice-to-voice режим с возможностью перебивать AI
- Проверить качество анализа на подготовленном наборе диалогов.
- Провести UX-полировку основных сценариев.
- Добавить продуктовую аналитику для ключевых этапов воронки.
- Подготовить приложение к пилотному тестированию на реальных пользователях.
- Провести внутреннее end-to-end тестирование критических сценариев.

### Результат недели

Стабильный MVP готов к пилоту: пользователь проходит onboarding, разговаривает с AI, получает
персональный разбор и задания, а следующая сессия учитывает его ошибки и прогресс.

## Критерии готовности MVP

- Пользователь может начать и завершить speaking-сессию в мобильном приложении.
- Voice pipeline стабильно обрабатывает последовательный разговор пользователя и AI.
- После сессии доступны transcript и анализ речи.
- Анализ охватывает Grammar, Vocabulary, Fluency, Speed of Speech и базовый Pronunciation.
- Пользователю показываются 2–3 приоритетных слабых места с примерами и рекомендациями.
- Система сохраняет историю сессий и накопленный профиль пользователя.
- Следующая speaking-сессия адаптируется на основе предыдущих результатов.
- Пользователь может получить индивидуальное задание по своим ошибкам.
- Основные ошибки и задержки pipeline измеряются и доступны для диагностики.

## За пределами MVP

- Собственная модель оценки произношения.
- Большая библиотека учебных материалов.
- Детальная визуализация долгосрочного прогресса.
