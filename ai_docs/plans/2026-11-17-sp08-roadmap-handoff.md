# SP-08 Personalized Roadmap handoff

Status: implemented in the SP-08 worktree; not deployed or live accepted.

After a successful v5.5 Trial Assessment, Foundation queues `roadmap.generate` when the learner has a practical goal and a target CEFR. The Python job reads the pinned catalog, current learning state, Topic Knowledge, and existing Tasks. It returns a proposed full four-skill sequence. Foundation checks the learning revision, goal revision, Trial transcript revision, and Topic Knowledge digest. It creates or reuses SP-04 Tasks and saves the sequence in one student transaction. Repeated job application uses the operation receipt; a changed assessment creates a new roadmap revision and retains the prior revision in history.

`GET /internal/foundation/v1/learning-roadmap` returns `schemaVersion: 1` and a student-scoped `roadmap` row. Its `document.sequence` contains `order`, `taskId`, `skillId`, `topicId`, `problemId`, `cefr`, `knowledge`, `provisional`, `reason`, `orderReason`, and `goalFocus`. The document also contains `goal`, `goalRevision`, `targetLevel`, `catalogVersion`, `assumptions`, `taskCount`, `history`, and `timeline: null`. `GET /learning-roadmap/history?offset=` returns older revisions. SP-09 owns later priority and next Task decisions; SP-10 owns timeline; SP-11 owns Telegram delivery. No entitlement check gates the roadmap read.

Initial selection includes catalog Topics from each skill's current level through the overall target, plus earlier recorded gaps. A system level is preferred; self-report is an explicit fallback. An unknown skill starts with provisional A1 coverage. Known Topics are skipped unless an existing Task was reopened. Existing active Task identities are reused. New Problem links and untested Topics are labeled provisional. Work or interview goals bring matching Speaking, Listening, and Vocabulary contexts forward within a level; general Grammar and all four skill paths remain.

The initial sequence is a conservative coverage proposal, not a certified CEFR curriculum or fixed prerequisite graph. Problem type is a hypothesis when Topic Knowledge lacks a Problem-level diagnosis. Product review should decide whether the inclusive topic coverage is too broad and whether richer evidence should choose Problem types. The initial order is level and goal based; it does not claim a unique pedagogical prerequisite relation.
