## Согласованный объём

Первый маршрут из уже согласованной цели сразу активируется после trial и объясняется в Telegram.
Пользователь выбрал это явно при уточнении SP06. Отдельное согласие нужно для смены направления.
Этапы — гибкая последовательность навыков на следующие недели, не сценарии всех будущих уроков.
Нет новых шкал, обещаний сроков освоения уровня или автоматического завершения этапов.
Экран My Progress и методика подтверждения навыка добавлены позднее в [SP-08](2026-11-12-sp08-progress.md).

## Реализация

План выполнен: pipeline, контекст, explanation/next topic, failure handling, локальные проверки и документация.

- `roadmap.prepare` использует прежние claim/lease/fence/apply/receipt. Запускается после актуального
  trial evaluation и при новых наблюдениях/исправлениях памяти. Нужна сохранённая цель.
  Создание regular также запускает отсутствующий roadmap для ранее обработанного trial.
- `RoadmapPlanner` возвращает strict schema: `revise`, `keep` или `insufficient_evidence`, reason,
  steps и sourceIds. Backend хранит прежние Roadmap/revisions/steps и проверяет ownership,
  goal/learning/roadmap revisions, актуальную transcript revision каждого источника и epoch.
  V42 добавляет только `foundation_job.result` для сохранения результата review, включая недостаток данных.
- Автономная адаптация сохраняет все id/outcome; меняет порядок и тактику. Требуются источники
  минимум из двух разных уроков и новые источники относительно прошлой версии.
  Это минимальная защита от единичной ошибки, не критерий освоения. Смысл повторяемости оценивает LLM;
  педагогическая корректность требует отдельной живой приёмки. Новая явная цель создаёт новый маршрут;
  старый маршрут другой goal revision не попадает в контекст.
- Один ContextBuilder передаёт roadmap/reason/sources, актуальные observations с lesson_id и состояние
  подготовки в Text/Voice/Learning. Старые transcript revisions исключены из observations.
  Исправления подтверждённых фактов обновляют learning revision и будущие планы.
- Существующий planner SP03 сохраняет `objective/topic/strategy`; strategy содержит релевантный
  личный контекст, поддержку и варианты развития беседы. Plan хранит roadmap_revision и evaluation refs.
  Jobs фиксируют lesson/goal/learning/roadmap versions. Перенос отзывает прежний job и plan.
  Начатый урок и reconnect используют прежний execution_snapshot.
- `lesson.next` возвращает `preparedTopic` только своей реальной следующей встречи с актуальным
  готовым планом. Null означает, что тема неизвестна; голос не подставляет текущую тему.
- Telegram объясняет сохранённый маршрут: барьер → цель → последовательность навыков и причины.
  Trial follow-up ждёт активные evaluation/roadmap jobs максимум пять минут от due_at, без изменения
  маркера подавления при новом сообщении ученика. Terminal failure прекращает ожидание.
  При отсутствии результата ответ честно обозначает это; не создаёт выдуманный roadmap.

## Ошибки и совместимость

Regular сохраняет entitlement SP05; trial бесплатен. Подготовка не выдаёт доступ.
Незавершённый анализ блокирует regular. `insufficient_evidence` — успешная обработка с явной
неопределённостью: план может опираться на известные факты без выдуманного маршрута.
`analysis_failed`, `roadmap_failed`, `plan_failed` видны при admission; Mini App предлагает написать
репетитору и перенести встречу. `lesson.list` также возвращает preparation для честного ответа в чате.
Оператор может явно повторить актуальную failed job через существующий `job.retry`; автоматического
восстановления старых DEV jobs здесь нет. Budget exhaustion не запускает автоматический retry.

Остаток инцидента подтверждён: backend ограничивал compute 45 секундами при lease 60 секунд.
Теперь AI endpoint ограничивает compute 120 секундами, HTTP — 140, worker — 150;
worker продлевает lease/scope каждые 20 секунд. Strict schemas и отсутствие общего token cap сохранены.

## Проверки

Полный Python → HTTP Ktor → PostgreSQL путь использует настоящие ContextBuilder, LearningEngine,
TrialAnalyzer, RoadmapPlanner и LessonPlanner; только model adapter возвращает подставной текст.
Проверяются trial → observations → roadmap → plan → voice context → observations → revision,
повторы receipts, поддельные источники, запрет смены outcomes, исправления фактов/цели,
frozen plan, платный regular/free trial, next topic/null, перенос во время compute,
недостаток данных и terminal failures. Kotlin проверяет длительное вычисление с настоящим
продлением lease и ожидание/отказ trial follow-up с подставным HTTP.
Историческая локальная проверка SP-06 выдержала 65-секундный compute с renewal и одной попыткой;
она не доказывает задержку реального провайдера.
Итоговые результаты — в [status.md](../status.md).

Старые successful analyses не получают roadmap job автоматически при deploy. Нет общего backfill;
разовый запуск для одного ученика не является исправлением всех старых данных. Просмотр прогресса не запускает compute.
Локальные mocks/PG не доказывают качество преподавания; живые результаты отдельно фиксируются в статусе.
