# Reminder to call continuity and one active reminder button

Status: implemented in PR #40; automated tests pass locally. Live DEV Telegram callback acceptance and deployment remain pending.

When a learner taps `🎙 Start call` on a practice reminder, the first spoken question must continue the topic of that exact reminder. Personalized generation returns a reviewed pair, `text` and `openingQuestion`, from the same verified source; invalid or unrelated pairs fall back to general copy. Every general practice template has a fixed corresponding spoken question. The reminder button refers to a stored record for that Telegram message, rather than carrying personal content in callback data. The call opens in ordinary free-conversation mode with that question; the persistent menu `🎙 Start call` stays independent and chooses its usual free opening. If a call is already active, tapping a reminder does not replace its conversation. A failed, undelivered reminder opening cannot leak into a later menu-started call.

At any moment, the most recently accepted automatic reminder in a Telegram chat owns the active reminder button. Send the new message first; only on acceptance, atomically mark its button active and the previous button inactive in PostgreSQL. Then remove the previous message's inline markup through Telegram. If removal fails, retry it in the background; a callback on the old message is already rejected server-side and directs the learner to the latest reminder. If the new send fails, the old button remains active. This applies to both stage-specific onboarding follow-ups and opted-in or inferred-time practice reminders. An old practice reminder remains actionable, with its original topic, until a newer reminder is accepted.

The database keeps the opening question only for the active button; superseding it clears the older question. Analytics continue to store the actual copy kind without raw personal content. Existing messages from before this rollout have no durable button records and cannot all be edited retroactively; this feature has not yet been deployed, so current PR reminder buttons have no deployed legacy population.

Automated acceptance covers the paired copy, one active button per chat despite session-ID format differences, stale callback lookup, failed reminder opening followed by a menu start, and free-call behavior after a reminder call. A DEV Telegram test must still confirm real `editMessageReplyMarkup` and voice delivery.
