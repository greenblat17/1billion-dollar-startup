## Решения интервью

- Объём: только foundation — хранение, чтение, обновление, интерфейсы для других компонентов и совместимость с Memory.
- Новые AI-writers из диалога и уроков не подключаем. Это следующие Onboarding, Post-Trial Assessment и Post-Lesson Review.
- Текущий уровень: общий и по каждому Skill, отдельно самооценка и оценка системы. Это диагностический профиль.
- Целевой уровень: один общий CEFR, без разбивки по Skills. Практическая цель хранится рядом, например B2 для общения на работе.
- Для Topic Knowledge сейчас определяем только контракт записи. Педагогические правила переходов относятся к будущему assessment.
- Topic Knowledge хранит текущее состояние и историю изменений с объяснениями и источниками.
- Механизм оспаривания Topic Knowledge не входит в SP-03. Несогласие и отказ изучать тему не меняют оценку автоматически.
  Выбор задач и уважение отказа реализуются в Learning Roadmap и Student Interactions; повторная проверка не обязательна.
- Обычное истечение срока хранения транскрипта не удаляет учебную оценку.
  Остаются результат, краткое основание и метаданные источника с признаком недоступности исходного текста.
- CEFR: одно значение A1 / A2 / B1 / B2 / C1 либо Unknown, с текстовым пояснением.
  Диапазонов нет. Выбор значения при неопределённости относится к SP-07 и SP-17.
- Интенсивность: конкретное число занятий в неделю и конкретная длительность в минутах; числа допускают null.
- Homework: согласие, конкретное количество минут и период day/week; числовое значение допускает null.
  Свободный текст и диапазоны нагрузки не являются полями предпочтений.
  Уточнение неопределённых ответов реализуется в Onboarding SP-05, не в SP-03.
- Существующих учеников нет; база пустая по сообщению пользователя. Backfill, legacy fallback и поддержка старых учебных записей не нужны.
- Учебные поля принадлежат Student Learning State. Старый код записи этих полей в Memory не сохраняется ради совместимости.
- Совместимость с Memory означает сохранение персональной памяти, а не сохранение прежней архитектуры учебных данных.
- Все решения и технический объём утверждены пользователем.

## Модель данных

1. **Student Learning State:** studentId, revision, текущий уровень, целевой уровень, ссылка на Learning Goal,
   дедлайн, интенсивность и Homework Preferences. Неизвестные значения допустимы.
2. **Текущий уровень:** отдельно самооценка ученика и оценка системы, с происхождением и основанием.
   Общий уровень и профиль по Skills сохраняются независимо: A1/A2/B1/B2/C1/Unknown и текстовое пояснение.
   Нет диапазонов и автоматического вычисления общего уровня из навыков.
   При недостатке данных — Unknown; выбор наиболее обоснованного CEFR выполняют будущие компоненты.
   **Целевой уровень:** единственное общее значение A1/A2/B1/B2/C1/Unknown, без целей по Skills.
   Оно описывает образовательную цель, а не диагностическую оценку; пара самооценка/оценка системы к нему не применяется.
3. **Topic Knowledge:** studentId, catalogVersion, topicId, одно из четырёх согласованных состояний,
   объяснение, источники, версия изменения; сохраняется история предыдущих оценок и их оснований.
   Отсутствие записи читается как Unknown.
   Known и Not Known требуют основания; Presumed Not Known хранит гипотезу явно.
   Ни отсутствие темы в речи, ни её CEFR сами по себе не создают подтверждённого пробела.
4. **Источники:** ссылки на Observation и его ревизию, урок/событие, происхождение и актуальность.
   Самоотчёт не становится демонстрацией навыка. Сырые транскрипты не копируются бессрочно.
   Истечение срока хранения исходного текста отмечается отдельно; оценка и её краткое основание сохраняются.
5. **Интенсивность:** согласованная доступность занятий, отдельно от фактического расписания.
   Поля: lessonsPerWeek и lessonDurationMinutes, конкретные числа либо null, без диапазонов и свободного текста.
6. **Homework Preferences:** согласие yes/no/unknown, minutes (конкретное число либо null), period (day/week либо неизвестно),
   источник и версия. Неизвестность не означает согласие; отказ не меняет цель или критерии освоения.
   SP-03 не уточняет значения через диалог и не назначает Homework.

Числовой mastery, confidence score, минимальное число примеров и автоматические переходы не входят в SP-03.
Релевантность Topic цели не смешивается с Topic Knowledge.

## Утверждённые технические решения

- Новые модели и операции выделить в `StudentLearningState`, не расширять несвязанные schedule/payment-методы `LearningState.kt`.
- Внутренний API предоставляет чтение профиля, частичное обновление профиля, чтение/запись Topic Knowledge и чтение истории.
  Запись доступна доверенному backend-компоненту с student scope; к tool-набору текущего AI эти операции не подключать.
- Пропущенное поле PATCH сохраняет значение; явный null очищает nullable-поле. Unknown уровня не заменять уровнем по умолчанию.
  Числа нагрузки положительные, конечные, без диапазонов; ноль не подменяет Unknown или отказ от Homework.
- Каждая запись проверяет expectedRevision и operationId. Повтор с тем же содержимым возвращает прежний результат;
  другой payload под тем же operationId и устаревшая revision отклоняются без частичного применения.
- Текущая оценка Topic и запись её истории обновляются в одной транзакции.
  История не обходит правила forget/delete и не является бессрочным архивом исходной переписки.
- Sources имеют тип, идентификатор и ревизию источника, контекст урока при наличии, автора/компонент и время оценки.
  Foundation проверяет принадлежность доступных источников. Для будущих Observations нужен явный контракт ссылки;
  полноценное извлечение Observations, их генерация моделью и педагогическая интерпретация остаются SP-17 и assessment.
  Не создавать фиктивные Observations для прохождения проверки.
- Known/Not Known сохраняются с основанием и источниками, Presumed Not Known — с явным обоснованием гипотезы.
  Проверка полноты записи не означает проверку педагогической достаточности evidence.
- Оценка привязана к версии каталога и Topic ID. Публикация новой версии не переписывает старые оценки автоматически.
  Чтение явно указывает версию; для темы без оценки в запрошенной версии возвращается Unknown.
  Автоматический перенос между версиями не входит в SP-03.
- Релевантность цели, отказ от изучения и приоритет задач не являются состояниями Topic Knowledge.
- Новый UI и объяснение изменений через диалог не создаются. Интерфейсы чтения содержат объяснение и источники для будущих потребителей.

## Проверки и критерии приёмки

- Состояние читается после рестарта и в следующем уроке; изоляция учеников соблюдена.
- Все четыре состояния различимы в БД, API и контексте. Непроверенное не превращается в подтверждённое.
- Самооценка и оценка системы не перезаписывают друг друга незаметно.
- Повтор команды не создаёт второе изменение; устаревшая версия и чужой источник отклоняются.
- Изменение цели/предпочтений не теряет другие поля; отказ от Homework не создаёт учебного штрафа.
- История Topic Knowledge сохраняет предыдущие оценки, основания и источники.
- Истечение срока хранения транскрипта сохраняет оценку и отмечает недоступность исходного текста.
- Нет механизма спора Topic Knowledge и автоматического изменения оценки из-за отказа изучать тему.
- Смена опубликованного каталога не перепривязывает старую оценку к новой семантике молча.
- Персональные Memory record/search/forget, candidates и ограничения упоминания работают.
- Учебные поля не записываются в Memory и не читаются из неё как запасной источник.
- Без подключённого AI-writer учебные поля остаются Unknown/null; чтение не вызывает скрытой записи или оценки.
- `/start`, delete и восстановление не возвращают удалённое учебное состояние.
- Kotlin unit + PostgreSQL integration + Python adapter/context tests + HTTP contract tests.
- После реализации: `pytest`; из `cmp/` с `GRADLE_USER_HOME=$HOME/.gradle` —
  `./gradlew :server:test :server:buildFatJar detekt`; integration по принятому репозиторному запуску.
- Приёмка SP-03 проверяет foundation через реальные API/БД и регрессию существующих потребителей.
  Живое автоматическое обновление через AI не входит в критерии этой задачи.
