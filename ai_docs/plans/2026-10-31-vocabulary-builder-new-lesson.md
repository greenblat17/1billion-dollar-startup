# Новый порядок урока Vocabulary Builder

Обновление 2026-10-31: новые уроки формата `5` проходят `Understand A → Use A → Understand B → Use B → … → Word game A → Word game B → …`. Это заменяет описанный ниже порядок формата `4` для новых запусков. Активные уроки формата `4` завершаются по прежнему порядку; обязательные карточки сохраняются. Кнопка прогресса для обоих форматов теперь показывает один значок на слово (`⚪️ → 🟡 → 🟠 → 🟢`) вместо общего счёта `0/3N`; внутренний индекс `0…3N` остаётся прежним. Текущий контракт — в [ТЗ урока](../product/2026-10-31-vocabulary-builder-lesson.md).

Статус: реализовано локально; DEV-приёмка реальными голосовыми уроками открыта. Продуктовый контракт: [новое ТЗ](../product/2026-10-31-vocabulary-builder-lesson.md). Существующие правила полного контекста остаются в [плане контекста](2026-10-29-vocabulary-lesson-context.md).

## Конкретная проблема

Текущий формат ведёт одно слово через `Understand → Use`, затем переходит к следующему, после чего задаёт отдельный `Recall` и предлагает необязательную игру. Это не даёт нужной паузы между знакомством со всеми словами и самостоятельным употреблением каждого. Игра не входит в обязательный урок. Короткое согласие ученика на первом шаге и естественный ответ без целевого выражения требуют разных реакций, но вопрос второго шага сейчас может допускать ответ совсем без выражения.

## Целевой автомат урока

Для `N = 1…5` слов и индекса `0…3N`:

```text
Understand A → Understand B → … → Use A → Use B → … → Card A → Card B → … → Finished
```

- В `Understand` Speaky объясняет одно выбранное значение и задаёт ясный вопрос о контексте. Подтверждения ученика достаточно; явную путаницу он разбирает до перехода. Целевое слово в ответе не обязательно.
- В `Use` Speaky задаёт новый вопрос без целевого слова. Внутренняя проверка требует полного естественного ответа с ним; пример ответа не показывается. Ученику нужна собственная уместная фраза. Естественный ответ без выражения — повод продолжить разговор на той же цели, а не ошибка. Небольшую побочную грамматическую ошибку можно поправить и перейти дальше.
- После последнего `Use` тот же голосовой ответ содержит короткий переход и первую карточку. Состояния `offer` и кнопок Play/Skip в новых уроках нет.
- Одна карточка на слово проверяет форму и значение. Направления чередуются; при одном слове используется `слово → значение`. После ошибки Speaky помогает без лимита. Первое “I don't know” вызывает подсказку; второе раскрывает ответ и завершает карточку. Нераспознанный голос не получает оценки.
- После последней карточки Speaky отправляет краткий итог по каждому слову. Досрочный `End lesson` и тайм-аут сохраняют частичный результат.
- Общий прогресс: `index/3N`; завершённая, но неугаданная карточка увеличивает `index`. Результат карточки хранится отдельно от понимания и употребления.

## Изменения в AI-сервисе

1. Повысить версию формата урока и маршрутизировать активные уроки прежнего формата по прежнему автомату до их естественного завершения. Нынешняя проверка `_legacy_lesson()` принудительно закрывает старый урок в `due()` и `end()`; это нужно заменить. Новый `start()` не должен затирать активный старый урок.
2. Заменить вычисление `_position()` и `_current()` для нового формата на три последовательных прохода. Сделать переходы явными по версии формата, а не выводить их из старого чётного/нечётного индекса. Удалить обязательный `Recall` только из новых уроков; старые продолжают прежний порядок.
3. Обновить `TUTOR_SYSTEM` и проверку структурированного ответа: один связный ход репетитора, фактологичная реакция на ответ, один законченный вопрос, естественный полный ответ с целевым выражением для `Use`. Вопрос не называет слово и не говорит “use <word>”. Неясное задание остаётся разговорным уточнением без смены цели. Не кодировать каталог конкретных реплик пользователя.
4. Добавить внутренний контроль вопроса `Use`: модель строит скрытый пример полного ответа, а приложение проверяет наличие целевого выражения и что пример отвечает всему вопросу. При неудаче переформулировать вопрос до отправки. Скрытый пример не включать в голос, субтитры или подсказку. Контроль не заменяет проверку качества реального вопроса в DEV.
5. Встроить карточки в тот же журнал и сборку контекста урока. Перевести `play()`/`skip()` в совместимый путь только для старых `offer`-уроков. Генерировать первую карточку в том же ходе, где принят последний `Use`. Для новых карточек убрать `cardAttempts >= 2`; различать неверный ответ, первое/второе “I don't know”, неуверенное распознавание и прямое завершение урока. Подсказки должны меняться и не раскрывать ответ до второго отказа.
6. Сохранять в результатах по слову `understood`, `used`, `card`, а для `Use` и карточки — сведения о подсказке. Пересчитать готовность к повторению через 24 часа после полного завершения нового урока. Не менять CEFR, Grammar и общий Vocabulary score.
7. Сохранить полную историю нового урока и исходные реплики по действующему механизму сжатия. Добавить в `review` события карточек, причины оценки, подсказки и переходы фаз. Одно Telegram message ID обрабатывается один раз; при ошибке генерации или доставки состояние не перескакивает через карточку.

## Изменения в Ktor и Telegram

1. Обновить контракт `VocabularyLesson` и отображение кнопки прогресса под новый общий `0/3N`. Для старых уроков оставить прежний вид по версии формата. Кнопка прогресса не является оценкой правильности.
2. Для новых уроков не показывать Play/Skip. Оставить `Subtitles`, `Hint` и `End lesson`; Speaky всегда отвечает голосом, в том числе на временный текстовый ввод. Первая карточка приходит в одной голосовой реплике после последнего `Use`.
3. Проверить обработку новых статусов в голосовом и текстовом маршрутах, напоминании через пять минут, тайм-ауте через час, повторной доставке и старых callback-кнопках. Старый callback не запускает карточку дважды и не переводит новый урок в старый путь.
4. Итог в чате отдельно показывает понимание, собственную фразу и карточку для каждого слова; неверная карточка не отменяет завершение урока. После завершения возвращаются кнопки для начала следующего урока.

## Проверка

- Тест автомата на 1, 2 и 5 слов: полный порядок, автоматическая первая карточка, итог только после последней карточки, частичный `End lesson` и тайм-аут.
- Тест репетитора: короткое “Yes” в `Understand`; естественный ответ без слова в `Use`; неясный вопрос; собственная фраза с небольшой побочной ошибкой; отсутствие лимита ответов и выдуманных фактов. Отдельная проверка, что скрытый пример ответа не попадает пользователю.
- Тест карточек: чередование направлений, одно слово, несколько неверных ответов без автоперехода, первый/второй “I don't know”, неуверенное STT и повтор одного message ID.
- Совместимость: заранее созданный активный урок старого формата проходит старые `Recall` и Play/Skip до конца; новый урок после него работает по новому формату. Старые кнопки не создают вторую игру.
- Kotlin-тесты для кнопок и контракта прогресса `0/3N`, включая неугаданную карточку и завершённый урок. Запустить тесты AI-сервиса и `:server:test` из `cmp/`.
- DEV-приёмка реальными голосовыми уроками с 1, 2 и 5 словами. Сопоставить фактические голосовые вопросы, ответы и основания оценки в `review`; отдельно проверить `small talk`, `figure out`, естественный ответ без слова и длинный разговор на одном шаге. Зелёные тесты без этого не закрывают качество репетитора.

## Локальная реализация и граница проверки

Новый формат — `4`; формат `3` остаётся на прежнем маршруте до завершения. `VocabularyBuilder` хранит новый индекс по трём проходам, проверяет вопрос `Use` на скрытом примере и отдельной оценкой модели, автоматически создаёт карточки и записывает переходы в `review`. Для новых карточек нет автоматического перехода после числа ошибок; два явных “I don't know” завершают карточку через подсказку. Telegram показывает общий `index/3N`, принимает временные текстовые ответы и продолжает отвечать голосом. Итоговая голосовая реплика и текстовая сводка различают результаты по словам.

Локально прошли тесты AI-сервиса и `:server:test`. Это подтверждает автомат и совместимость на подставных моделях; качество реальных вопросов, карточек и задержку отдельной проверки `Use` ещё нужно измерить после развёртывания в DEV.
